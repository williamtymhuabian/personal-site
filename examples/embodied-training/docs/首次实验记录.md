# 首次停车候选训练：先把失败解释清楚

执行日期：2026-10-23。数据生成、NumPy 训练与 Node 仿真均为本地的小规模工程验证；没有提交服务器作业，没有训练视觉模型、语言模型或控制真实设备。

## 可回查记录

原始数据：用固定种子生成的停车数据；三个训练种子：`sample-results/parking-v1/seed-7`、`seed-19`、`seed-43`。每个种子有权重、161个训练/验证损失点、分类指标、320条仿真回放记录。此早期运行的报告先于后续补充的 manifest 字段，因此不含后来增加的候选覆盖和训练源码摘要；新服务器入口会记录这些字段。保留原运行，不补写不存在的历史元数据。

现有核心 SHA256 为 `29595a1803c2cfbb402c8a8af0f74651c869d5fcdc1fa7a651b734f5b8072a90`。数据有192个目标、每目标48个候选，共9,216条记录。96/32/32个训练/验证/测试目标；额外32个目标在更远的 y 范围，用作压力测试。

这是一个固定桌面布局下的窄任务，划分单位是目标位置所在空间单元，不是不同房屋；邻近单元依然相关。不能将结果表述为跨房屋或真实机器人泛化。

## 观察到的事实

三个种子的初始训练 BCE 分别约0.7568、0.6966、0.7672；最佳验证 BCE 分别约0.00741、0.00618、0.00646，对应第152、159、160轮。权重确实被优化。

测试候选共有1,536条，其中39条通过端点可行检查；分类平衡准确率分别约99.97%、98.65%、99.93%。不过测试集总是预测不可行也有约97.46%的普通准确率，说明仅报准确率会夸大效果。

在32个测试目标中，只有9个至少有一个采样候选通过底盘间隙和阶段端点检查。三种子完整回放的计数一致：

- 原固定停车位：成功6，失败26。
- 距初始底盘最近的候选：成功0，失败32。
- 按距离依次几何校验：成功9，拒绝23。
- 模型直接取最高分：成功9，失败23。
- 模型排序后几何校验：成功9，拒绝23。

后四种方法使用相同候选集合。固定停车位保留原规则，不保证在这个采样集合中。这里模型没有超过几何校验的任务成功数。模型排序加校验的端点检查均值约34.78次，按距离校验约41.22次；这只是检查次数，不是实测总延迟优势，不能忽略网络推理和排序成本。

分布外32个目标共1,536个候选全部不通过端点检查。两种带校验方法全部拒绝，其他三种方法全部失败。分类准确率100%在这里不意味着完成任何任务，也不足以证明模型泛化。

上述候选可行仅指这套网格与模型；不能据此断言真实机器人或更完整停车搜索一定无解。当前样本中没有通过检查的分布外候选，所以下一版需要另外设计“分布外但仍有可行解”的任务，才能评价泛化能力。

## 下一步实验怎么改变

先分析候选不足：区分桌面间隙、预抓取高度和关节限制；在训练/验证集扩展更密的前侧候选或受约束侧向候选，并建立新的封存测试集。保留当前结果，不用试过的测试集挑网格。

几何规则在小规模模型里已经很便宜。如果模型不能在更多目标、噪声或复杂约束下带来实际收益，就保持几何方法，转而研究观测变化与恢复策略。这个失败结论本身可以成为训练平台的教学案例，不应包装成专利技术效果。
