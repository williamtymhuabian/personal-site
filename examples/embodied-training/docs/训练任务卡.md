# 训练任务卡：每次读书都留下课题证据

本任务集是原创练习设计，不是原书练习或代码的重印。Agent 书依据 v1.3；另外两本已核对用户本地 PDF 目录。网站稳定引用 ID 见 `curriculum.json`。状态只描述工程准备程度，不会替用户标记已学会。

## T01：重现一个真实存在的失败（已提供入口）

读 Agent 第1、4、6章。运行 `node --test tests/pickgo_adapter.test.cjs`，找到 y=0.76 与 y=0.96 两例。解释为什么同一个任务和动作序列会分别成功与失败。

练习：只修改测试副本中的目标 y，保持底盘规则与机械臂参数不变；记录失败阶段，区分“目标点不可达”和“预抓取位不可达”。提交参数、核心版本、两条完整输出和自己的解释。不要仅提交成功截图。

## T02：从样本到真正的参数更新（已实现）

读 Agent 第7章、LLM 第5章的训练/验证损失与附录A。运行 README 的服务器入口；看 `history.json` 的损失如何变化，再从 `model.json` 确认权重、均值和标准差已保存。

练习：说明特征、标签、损失、优化器和检查点选择分别是什么。解释为什么训练集与测试集必须按目标场景分组，为什么标准化只能读训练集。当前是 MLP 监督学习，不是原书的语言模型预训练。

完成标准：新目录能重跑；三个种子均有记录；能指出全负样本准确率的陷阱，并解释为何保存最佳验证损失的权重。

## T03：让评测回答“模型帮了什么”（已有基础，待扩展）

读 Agent 第6章。比较 fixed、nearest、geometry_verified、mlp_raw、mlp_verified 五个方法，查看每种方法的失败和拒绝数量。

练习：把“成功”“失败执行”“候选不足而拒绝”分开报告；统计同一候选集合内至少有一个可行项的场景数。当前较远目标均无通过端点检查的候选，因此不能用它证明模型在分布外泛化良好。

扩展：预先制定更密或侧向停车网格，作为新的实验版本；重新生成、分组、训练和评测，不用已观察过的测试结果反复挑选最好配置。必要时建立新的封存测试集。

## T04：把书中的上下文变成机器人轨迹（待实现）

读 Agent 第2、4、9章。设计 JSONL 记录：`episode_id, step, observation_id, captured_at, received_at, scene_id, calibration_version, action, preconditions, result, source`。

练习：区分采集时刻和接收时刻；保留时钟来源。注入延迟、重复、乱序和丢帧，验证依赖旧观测的动作会重新验证。评测器的几何真值只用于评分，不能混入 Agent 输入。

完成标准：同一录制能从初始状态重复回放；状态未知不写成成功；每个动作可以追到依据。断点续演需要完整控制器状态，不能只靠当前 PickGo 快照。

## T05：比较检索方式（待实现）

读 Agent 第3章，GraphRAG 第2、3、6、8章。建立房间、物体、关系和带来源观测的小数据集，人工标出查询对应证据。

练习：比较关键词、向量、图邻域与混合检索；同时测 Recall@k、排序指标、证据过期率、耗时和存储。测试房间/模板与训练数据隔离；语言改写不能被当成新场景。

完成标准：列出图检索比简单方法好和差的例子；解释为什么文本知识图谱方法移到空间记忆时还需要几何、时刻和动作验证。第一版可用 JSON 邻接表；本任务不要求一开始部署数据库。

## T06：训练一个记忆重排器（待实现）

读 LLM 第6章、GraphRAG 第8章。先冻结表征模型，用任务、观测匹配、距离和时效特征训练轻量排序器，再考虑 Transformer。

练习：每条查询包括正证据、语义相似却过期的难负例、其他房间的负例；按场景分组。比较固定加权、仅语义、仅新近度与学习排序，保留相同检索候选。

完成标准：报告样本来源、标注准则、训练曲线、三个种子、检索与下游任务结果；不得将相邻视频帧随机拆到训练和测试中。

## T07：从零理解 Transformer，再做任务 SFT（待实现）

读 LLM 第2—5章、Agent 第7章：用自建的小规模动作序列语料验证 token、因果 mask、loss 和生成循环。此阶段目标是理解训练机制，生成格式正确不能代替任务成功。

再读 LLM 第7章/附录E，整理任务指令、可获得观测、工具调用和实际结果，服务器上比较冻结模型提示、SFT/LoRA。基础模型、revision、精度、环境依赖和模型使用条件需确定后写入正式配置；本目录尚未提供该训练器或下载模型。

完成标准：输入与目标 token 的监督位置明确，工具结果与模型动作分角色；没有把未来观测当输入；输出需经过相同执行器和任务评测。论文可用结果必须来自下游实际执行。

## T08：失败驱动补数据（待实现）

读 Agent 第8章。用训练/验证中的错误制定下一轮采样：遮挡、旧记忆、候选不足、坐标误差分别补齐。与随机补相同数量的数据对照。

完成标准：数据版本和旧基线都保留；评测用封存测试；新增数据没有让旧任务明显退化。若声称持续学习，需要有跨轮分布、遗忘指标和更新协议，普通重新训练不能直接称为持续学习成果。

## T09：恢复策略与强化学习（已有热身，课题策略待实现）

已提供 `scripts/grid_rl.py` 做 Q-learning 参数更新热身，使用自建网格，并非腾讯开悟或机器人恢复环境。再按《腾讯开悟实践指南》准备选定赛道的服务器基线。

读 Agent 第7—9章。先用经过验证的轨迹做行为克隆，动作限定为重新观察、换停车位、继续、等待/请求帮助。增加固定预算和终止条件，防止无限重试。

再比较行为克隆与强化学习，奖励含任务完成、错误执行、必要的拒绝和额外观测成本；数值预先写入配置。检查策略是否通过一直拒绝或提前结束获得虚高奖励。

完成标准：同一环境和动作预算、至少三个种子、成功/错误/拒绝/成本分开报告；仿真结果不外推到实体设备。
