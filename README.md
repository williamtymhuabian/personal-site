# Williamtym · 探索手记

一个受 Hexo 博客形式启发的轻量个人网站。支持 Markdown 写作、分类、归档、全文搜索、主题切换、计算机交互实验室、论文页、收藏与交流入口、竞赛与成果筛选、人工材料核验申请，以及 CSDN/小红书/抖音发布稿整理和 RSS 订阅。适配手机和桌面。

这是独立的静态博客实现，不是 Hexo 安装包；不需要 npm install、数据库、第三方字体或 CDN。运行生成器需要 Node.js 18 或以上。本机已检测到 Node.js 和 Git。

## 立即查看

双击 `index.html` 即可查看完整网站（包含搜索和文章）。也可以在 PowerShell 中执行：

```powershell
Set-Location -LiteralPath 'C:\Users\ASUS\Desktop\自媒体\personal-site'
node build.mjs --serve
```

浏览器访问终端打印的地址，默认是 http://127.0.0.1:4173 。按 Ctrl+C 停止服务。如果端口占用，可在同一个 PowerShell 中先执行 `$env:PORT = '4174'` 再启动。

## 写新文章

在 `content` 中创建一个 UTF-8 Markdown 文件，例如 `my-first-experiment.md`。文件名用小写英文、数字和短横线，不能与已有文件重名。格式如下：

```markdown
---
title: 我的第一次小实验
date: 2026-10-16
category: 技术实践
summary: 用一句话说清这次解决了什么问题。
tags: 实验, 学习
pinned: false
---

## 问题是什么

这里开始正文。

## 我怎样尝试

- 第一步
- 第二步

## 结果与限制

写出实际结果，也留下尚未解决的问题。
```

保存后，在项目目录运行：

```powershell
node build.mjs
```

生成器会更新根目录 `index.html`。请编辑 `content/*.md`，不要直接在生成后的 `index.html` 里改文章，否则下一次生成会覆盖。

默认分类为建站手记、技术实践、历史阅读、随记。也可以使用新分类，导航中的分类与数量会自动统计。初始文章由建站时起草，作为可编辑的开站内容；不代表已经在其他平台发表或是既往个人复盘。二分查找与二维导航均为说明性实验。

## 支持的 Markdown 范围

支持一级到三级标题、段落、粗体、行内代码、有序/无序列表、引用、分隔线、HTTPS/HTTP 链接和围栏代码块。代码块可用三个反引号或三个波浪号包围。暂不支持表格、嵌套列表、Markdown 图片、原生 HTML 和完整 CommonMark 扩展。

文章的原生 HTML 会转义显示，不会作为脚本执行。博客是纯前端静态站点，文章地址采用 `#/post/文章名`，无需配置服务器重写；支持 GitHub Pages 子目录。

## 文件职责

- `profile.json`：个人资料、社交账号与申请联系渠道。
- `data/awards.json`：仅含可公开的竞赛、参赛、认证和成果摘要。
- `data/projects.json`：可持续更新的项目列表与关联奖项。
- `content/`：Markdown 文章源文件。
- `src/template.html`：页面 HTML 模板。
- `assets/`：页面样式、交互代码和图标。
- `build.mjs`：零依赖生成器与可选本地预览服务。
- `privacy.mjs`、`privacy.test.mjs`：公开数据与文件检查、对应测试。
- `index.html`：生成好的网页，应一起提交到 GitHub。
- `.nojekyll`：让 GitHub Pages 按静态文件发布。
- `.gitignore`：忽略依赖、日志、临时文件和本地配置。
- `GIT_GUIDE.md`：以当前项目为例的 Git 与 GitHub Pages 操作说明。
- `UPDATE_GUIDE.md`：更新奖项、项目、证书索引与各平台发布稿的方法。
- `feed.xml`：构建时自动更新的 RSS 订阅。
- `.private/`：仅在本地保存的证书索引，已被 Git 忽略，不参与网页生成。

## DDL 投稿记事本

“DDL 记事本”拥有独立导航和页面（`#/notebook`）；“期刊与会议”（`#/venues`）保留原目录展示、筛选和官网／文献索引链接，不再嵌入记事本。记事本预置覆盖十个计算机方向的 18 条参考事项：已核对的截止日期、待核对的官网导航，以及期刊常规投稿指南。每条保留独立官网／CFP 链接、核对日期、轮次和前置条件；不从 CCF 类别推断 DDL。来源与日期记录在 `data/venue-deadlines.json`，最后核对为 2026-10-17，数据不会自动追踪官网变化。

点击“加入我的记事”后可编辑备注、完成状态和提醒；也可在独立记事本中新增事项，选择目录内的任一期刊／会议，或记录目录外期刊、专刊和个人计划。个人记录使用独立的 localStorage 键 `william-deadline-notebook-v1`，与原有候选、准备笔记分开保存，不上传到 GitHub 或留言区。JSON 备份可导出、合并导入，最多 500 条；导入失败不变更已有记录。删除后可撤销。

日期用官网本地时间与明确 UTC 偏移记录，支持 AoE（UTC−12），自动显示北京时间。夏令时地区需按截止当日偏移核对，不能直接把 PST、PDT 等混用。常规投稿和日期待核对条目不生成倒计时；个人计划另有标记。主论文、摘要注册、修订和补充材料分为不同事项。

DDL 日历导出 UTC 时间，可选提前 1、3、7 天或不提醒；仅导出带日期且未完成的个人记录。请将 ICS 导入日历应用并检查通知设置，网页不会在关闭后推送通知。原有准备台导出的全天个人计划日历保持独立。备份包含个人备注，请自行保管。

## 欢迎与访问统计

`assets/visitors.js` 提供可关闭的欢迎提示，使用当前浏览器记录区分初次见面与回访。该判断不代表识别真实个人；清除浏览器数据或换设备后会重新判断。

页脚通过 [不蒜子公共节点](https://busuanzi.9420.ltd/) 的 API 获取全站访问次数（PV）。每次完整打开或刷新页面请求一次，站内 hash 路由切换不重复计数；不展示独立访客数，不补造接入前历史数据。当前 API 地址来自该节点公开脚本：https://bsz.iirose.cn/api 。本地、离线及非正式站点预览不发计数请求。

请求仅标注 `profile.siteUrl` 中的公开站点地址，不附带页面搜索参数、笔记、邮箱或其他本地存储内容；不加载第三方统计脚本，也不保存服务返回的身份标记。服务仍可获取 IP、User-Agent 等常规网络信息，并按其规则处理数据。浏览器的 Do Not Track / Global Privacy Control 信号会阻止请求；也可在页脚“统计说明”中停用后续统计。服务超时或响应异常时显示“暂时无法读取”，不会伪造数字或自动重试累加。公共节点无可用性和历史数据完整性保证。
