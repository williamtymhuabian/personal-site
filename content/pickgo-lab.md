本文记录2026-10-17的搬运仿真实践。后续的RGB摄像头接入另记在[摄像头与深度开发实践](https://williamtymhuabian.github.io/personal-site/#/post/pickgo-lab-camera)，两篇分别说明各自阶段的功能与验证范围。

如果要验证一个“移动到目标附近、抓取物体、运输并投放”的机器人流程，除了看最终动画，还需要知道：动作推进到了哪一步，暂停后能否继续，不同控制入口看到的状态是否一致，以及视觉函数到底输出了什么。

PickGo Lab把这些环节放进一个轻量环境：浏览器显示底盘与机械臂运动学仿真，本机Python服务持有场景，MCP提供工具入口，视觉页面单独检查原检测函数的输入输出。

项目地址：[williamtymhuabian/pickgo-lab](https://github.com/williamtymhuabian/pickgo-lab)。

当前项目适合学习和验证任务流程、初步几何可达性及接口联调。自动搬运使用简化场景中的几何位置；视觉检测可以单独验证，尚未接入搬运动作的反馈闭环。下面按实际运行方式介绍。

## 一、先跑起来：离线演示与共享仿真

最简单的体验方式，是下载项目后用现代浏览器打开根目录的`index.html`。这个页面可以单文件离线运行，无需安装Python、Node.js或npm依赖。

页面中可以选择红、蓝、黄方块，观察机械臂取物、托盘固定、底盘绕障运输和投放流程，也可以手动调姿、暂停、继续、停止和导出状态。

如果希望网页、Python脚本和MCP客户端控制同一个场景，则需要运行本机服务。先准备Python 3.10+ 和Node.js 18+，再执行：

~~~bash
git clone https://github.com/williamtymhuabian/pickgo-lab.git
cd pickgo-lab
python -B app.py
~~~

浏览器打开[本机运动仿真页面](http://127.0.0.1:8767/)。服务仅监听本机地址，其他读者需要在自己的电脑上启动；这个地址不是公共在线演示。

共享运动仿真不需要安装NumPy或OpenCV，也不需要执行`npm install`。视觉功能的依赖可以按需安装。

如果默认端口被占用，可以运行`python -B app.py --port 8768`，并把浏览器和MCP配置中的端口一起改成8768。按Ctrl+C可以关闭服务。

## 二、一个搬运任务怎样推进

运动核心在`simulator-core.js`中，包含简化四轴机械臂与差速底盘模型、正逆运动学、底盘A* 寻路，以及任务状态机。

一段搬运任务会经过取物、放置到托盘、收臂、移动、再次取物、投放和收拢等动作。把这些动作组织成状态机，便于观察中间状态，也能处理重复启动、暂停和取消。

- `RUNNING`：任务正在推进。
- `PAUSED`：暂停，保持当前位置，之后可以继续。
- `SUCCEEDED`：后置条件校验通过，目标已投放且机械臂已收拢。
- `FAILED`：任务执行或后置条件校验失败。
- `CANCELED`：任务被停止，保留当前物体状态。

这里需要区分“停止”和“重置”。停止会保留当前状态；重置才恢复初始场景。持物过程中停止任务，不能直接假定物体已经回到原位。

底盘路径规划使用A*，并按障碍膨胀后的间隙检查路径；运动中也有收臂互锁和底盘碰撞边界检查。机械臂仍是简化运动学模型，没有完整的机械臂碰撞检测，也不计算抓取力、摩擦和惯性。

## 三、让网页、Python与MCP使用同一份状态

项目中的控制链路可以概括为：

~~~text
网页操作 ───────────────────────→ app.py
Python 脚本 → utils.py ─────────→ app.py
MCP 客户端 → mcp_server.py
                    ↓
                 utils.py ─────→ app.py
                                    ↓
                           simulator-worker.cjs
                                    ↓
                            simulator-core.js
~~~

默认共享模式下，`app.py`持有仿真进程，网页、Python动作函数和MCP入口读取同一场景的状态。

`instance_id`用来区分场景实例，`task_id`用来区分某一次搬运。发起任务后，接口会立即返回任务标识，再通过`get_robot_state`查询运行结果。

任务标识也用于避免误判：如果查询时`task_id`已经改变或清空，说明原任务可能被重置或替换，不能据此宣布原任务成功。

在共享模式下，关闭网页或断开MCP客户端，不会取消已经被服务接收的任务。需要停止时，应显式调用停止操作。

如果只想用Python调用项目动作，可以先启动`app.py`，再打开第二个终端执行现成示例：

~~~bash
python -B examples/pick_and_send.py
~~~

这个示例展示了初始化、启动红色目标搬运、按任务标识查询结果，以及超时或中断时停止对应任务的处理。

## 四、MCP接入：把动作作为工具暴露出来

PickGo Lab提供轻量的stdio MCP服务。下面是常见`mcpServers`配置形式，脚本路径需要替换成你自己电脑上的项目绝对路径：

~~~json
{
  "mcpServers": {
    "pickgo-lab": {
      "command": "python",
      "args": [
        "-B",
        "C:/projects/pickgo-lab/mcp_server.py",
        "--server-url",
        "http://127.0.0.1:8767"
      ]
    }
  }
}
~~~

先运行`app.py`，再让客户端启动`mcp_server.py`。不同客户端的配置位置可能不同；仓库提供的是服务入口和配置示例，不能把这份JSON当作所有客户端通用的安装步骤。

当前可用工具包括：

- `get_capabilities`：读取当前仿真能力和限制。
- `get_robot_state`：查询场景与任务状态。
- `grab_and_send`：启动指定目标的搬运任务。
- `pause_task`、`resume_task`、`stop_task`：管理任务生命周期。
- `reset_scene`：恢复初始场景。
- `det_color`：对传入图像运行原视觉检测函数。

例如，`grab_and_send`的工具参数可以是：

~~~json
{
  "target": "blue",
  "speed": 3
}
~~~

目标支持`red`、`blue`、`yellow`，速度支持1、3、6。启动成功后要继续查询状态，不能把“工具调用已返回”当作“物体已搬运完成”。通信失败时也不自动重发动作，应先查询当前状态。

当前服务实现经典MCP的stdio/tools子集，不是完整MCP实现。`task_id`是本项目的业务字段，不代表支持MCP tasks扩展；本机`/api/*`接口也不是MCP HTTP传输端点。具体范围见仓库的[MCP接入说明](https://github.com/williamtymhuabian/pickgo-lab/blob/main/docs/mcp.md)。

另有`--standalone`模式，会建立独立场景；它与已经打开的网页不是同一个场景。需要网页与工具同步时，使用前面的共享模式。

## 五、视觉验证：复用原函数，单独检查输入输出

如果需要视觉功能，在项目目录安装可选依赖后启动服务：

~~~bash
python -m pip install -r requirements.txt
python -B app.py
~~~

然后打开[本机视觉验证页面](http://127.0.0.1:8767/vision.html)。

页面支持合成RGB-D测试图、本地RGB图片、目标颜色与位置变化，以及无目标、无效深度等情况。输出包括检测框、中心、像素偏差、原始矩形角度和有效深度。

项目复用`legacy/utils.py`中的`det_color`、`det_rect`和`col_dict_daylight_shelf_1`。适配层通过AST白名单提取指定定义，不导入整个原模块，避免触发原工程的ROS、串口或机器人初始化。

原文件按字节保留，来源清单记录了SHA256，测试也会检查一致性。原代码与新实现的范围在README中分别说明，原始代码的归属沿用源项目。

视觉验证当前使用可控二维RGB-D输入，没有生成三维场景的真实相机投影，也没有把检测结果用于自动搬运闭环。没有有效深度时，接口不会补造距离。这样可以先把函数本身的行为检查清楚，再讨论后续系统集成。

## 六、如何验证这个项目

本篇对应2026-10-17的测试记录，当时共有27项测试通过，分为运动核心、视觉接口和MCP／共享状态集成三组。后续增加摄像头功能后的测试范围见另一篇实践记录。

~~~bash
node tests/simulation.test.cjs
python -B tests/test_vision.py
python -B tests/test_mcp.py
~~~

- 运动测试9项：检查正逆运动学、绕障、三种目标搬运、互锁、暂停和取消等。
- 视觉测试9项：检查颜色、中心、角度、有效深度、空轮廓和原文件完整性等。
- MCP与集成测试9项：检查协议握手、工具参数、任务生命周期、本机接口，以及网页与MCP共用状态等。

这些测试验证的是当前程序的行为，不代表实体机器人上的效果。实际运行环境、边界条件和硬件接入仍需分别验证。

## 七、当前阶段与后续方向

这一版把离线演示、共享控制和视觉函数验证整理到了同一个项目中，方便分别运行、观察和复现。原生厂家SDK、ROS工程和真实设备后端没有包含在这个轻量仓库里。

后续可以继续探索三件事：生成与三维场景一致的相机投影；让检测结果参与搬运反馈；在完善模型、限制和状态校验后，通过独立后端接入真实设备。这些属于后续工作，当前版本尚未实现。

第一次使用可以先打开离线页面，观察任务状态，再启动本机共享服务。遇到问题时，保留输入、操作顺序和任务标识，会比只看最终动画更容易定位。
