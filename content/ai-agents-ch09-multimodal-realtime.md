一个系统能看懂一张图，不代表它能在图还在变化时正确行动。用户说到一半改了主意，界面刷新了，或者物体移动了，之前的判断即使当时正确，也可能已经不适合现在执行。

本篇对应李博杰《深入理解 AI Agent：设计原理与工程实践》PDF v1.3 第9章“多模态与实时交互”，书内第246—271页，对应 PDF 第254—279页。重点是语音对话、GUI 操作和机器人控制中的持续感知、延迟与反馈。

## “支持多种输入”与“能够实时交互”不同

静态任务可以先收齐材料再生成回答；实时任务中，输入和输出可能同时进行，而且后续输入可能推翻已经形成的计划。

因此除了理解内容，还要管理时间与状态：这条结果基于哪次观察，是否已经过时，用户是否打断，当前动作是否仍然符合目标？只测一张图片的识别准确率，覆盖不了这些问题。

评估也要覆盖完整链路。首次输出很快，但答到一半卡住，用户体验仍可能不好；模型处理很快，但语音分段、网络或工具执行很慢，端到端延迟也不会因此消失。

## 语音架构有不同的能力与代价

级联方案把语音识别、语言处理和语音合成分开，模块易于替换和定位问题，但边界处可能引入等待，也可能丢失语气等信息。把各环节做成流式，可以减少部分等待，但不自动解决所有轮次和打断问题。

端到端模型把多种处理放进更统一的系统，有机会减少中间转换，却也需要新的可观测性与控制方式。端到端不等于全双工：是否能够边听边说、区分自己的声音与用户输入、处理重叠发言，是另外的交互能力。

“快响应”和“深度处理”也可以分工，但接口必须清楚。快速模块不能随意替慢模块编造结论；慢模块完成后，要检查用户目标是否已经变化，而不是把旧答案硬接到新对话里。

## GUI 和机器人需要把观察绑定到动作

GUI 操作需要把“提交按钮”定位到真实界面元素或坐标。结构化元素信息与图像各有适用范围；界面变化后，原来的元素和坐标都可能失效。执行后还应读取新状态，不能把一次点击调用成功当成业务提交成功。

机器人控制增加了物理连续性。高层规划决定目标与步骤，低层控制需要适应传感器、动力学和接触反馈。VLA 把视觉、语言和动作联系起来，但模型输出还要经过适合设备的控制与约束层。

仿真与现实的差异也不只在画面，还包括摩擦、时延、标定和数据分布。某个训练场景完成抓取，不能直接推出它能在所有物体与环境里工作。

## 动手：旧请求的迟到结果应该去哪儿

下面把交互切成带版本号的事件段。打断后提高版本，迟到的旧结果就不能再进入当前输出。练习只处理内存里的字符串事件，使用 Python 标准库。

保存为 `realtime_epochs.py`，运行 `python realtime_epochs.py`。

```python
"""Chapter 9: event ordering simulation; no audio, GUI, robot or network is used."""
class Session:
    def __init__(self):
        self.epoch = 0
        self.partial = ""
        self.accepted = []

    def begin(self):
        self.epoch += 1
        self.partial = ""
        return self.epoch

    def interrupt(self):
        self.epoch += 1
        self.partial = ""

    def receive(self, epoch, text, final=False):
        if epoch != self.epoch:
            return "discarded"
        self.partial += text
        if final:
            self.accepted.append(self.partial)
            self.partial = ""
        return "accepted"


if __name__ == "__main__":
    session = Session()
    old = session.begin()
    session.receive(old, "尚未完成的旧回答")
    session.interrupt()
    new = session.begin()
    print("旧请求迟到结果：", session.receive(old, "继续旧回答", final=True))
    print("新请求结果：", session.receive(new, "只保留新任务结果", final=True))
    assert session.accepted == ["只保留新任务结果"]
    print("已接受：", session.accepted)
```

旧结果返回 `discarded`，新结果被接受，最终列表只保留新任务的内容。这个程序演示事件归属判断，不是语音识别、视觉定位或机器人控制模型，也没有测量交互延迟。

这里丢弃的是尚未接受的结果。已经播放的声音、已经提交的表单或已经发生的机械运动，不能靠修改版本号撤回；外部副作用需要单独的状态确认与恢复机制。

可以增加分片序号，处理同一条事件被重复发送；再模拟“结果完成后收到用户打断”，明确哪些输出仍应保留。真实系统还需要缓冲、背压、超时和资源取消，版本号只是其中一个小部件。

## 评估实时系统时，记录它看见的是哪个世界

一段可用的轨迹可以包含观察标识、时间、任务版本、动作、执行结果和下一次观察。这样才能区分“认错目标”“看对了但动作太晚”“工具执行失败”等不同原因。

还应分别记录首次响应、完整完成、打断生效和恢复所需的时间，并对不同网络与环境条件做测试。不要用一次顺畅演示替代所有条件下的交互质量。
