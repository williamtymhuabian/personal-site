王者荣耀强化学习的解题思路，可以从一个具体问题开始：同一份模型，为什么训练回报在涨，却未必更会赢？原因可能在任务目标、动作语义、奖励尺度、对手分布或评测方式，而不一定是算法不够新。

这篇给出一条面向服务器实验的工作路线。官方协议事实、社区作者经验与本站提出的实验方案分别注明；本次没有运行开悟环境，也没有验证下述改动能提高比赛成绩。参赛经历及已核对的公开记录仍见 [原训练文章](#/post/kaiwu-rl-server-practice)，个人正式奖级待证书确认。

## 先固定赛段：有些“王者1v1”目标并不相同

[旧版 HoK 首个智能体教程](https://aiarena.tencent.com/hok/doc/quickstart/first_agent.html) 以摧毁敌方水晶为目标，而 [2026智能体决策赛道页面](https://tencentarena.com/aiarena/zh/match/open-competition-2026/open-competition-2026-1) 的区域赛决赛介绍为先摧毁对方水晶前防御塔；初赛又是追逃任务。该2026页面核对时已结束，不是当前报名通知。

因此，2023/2024的参赛经验、公开 HoK 环境和2026特定赛段不能合并为一份规则。真正开始训练前，先写一页任务契约：

- 年份、赛道、赛段、开发包版本及代码提交号。
- 获胜、失败、平局、超时和异常退出分别怎样判定。
- 英雄、阵容、地图与阵营是否固定，哪些信息允许输入模型。
- 动作头、合法性约束、推理频率和提交格式是什么。
- 官方评估如何匹配对手，允许使用哪些历史数据和计算资源。

完成标准是能用一份对局日志解释一次胜负判定。若训练仍奖励打水晶，评估却以拆前塔结束，单纯调学习率解决不了目标不一致。

## 已找到的直接参考

[腾讯官方 hok_env](https://github.com/tencent-ailab/hok_env) 提供环境、训练框架和 PPO 实现；[1v1目录](https://github.com/tencent-ailab/hok_env/tree/master/aiarena/1v1) 包含 actor 与 learner；[集群说明](https://github.com/tencent-ailab/hok_env/blob/master/docs/cluster.md) 可用于理解采样和学习的衔接。阅读这些公开代码后，仍须回到实际赛段 SDK 确认接口和运行条件。

另外找到 [bianyh 的2026区域赛决赛复盘](https://github.com/bianyh/2026-Tencent-AI-Arena-D1-Regional-Final)。作者自述取得区域赛第三名，本次未独立核验名次。其公开思路包括 PPO、实体分组编码、分英雄分支、LSTM、多动作头与目标嵌入，并讨论裁剪复杂奖励。适合带着问题阅读：这些改动分别解决什么错误，是否提供等预算消融？不能据一份复盘就认定每项改动都有效，也不把其中的观测维度、序列长度照搬为通用协议。

## 第一步：让官方基线成为可重复的起点

先保持所选 SDK 的基线网络、奖励和采样配置，跑通训练、保存、加载、推理与评估。第一份记录应包含环境版本、基线提交号、种子、真实环境步数、训练用时和模型选择规则。

如果只能在部分对局运行，先修复异常；如果模型加载后行为与训练评估不一致，先检查预处理和推理模式。没有可重复的起点，就无法判断“增加 LSTM”究竟改善了策略，还是顺便修复了其他问题。

这一步选择官方 PPO 的理由是减少接入变量，不是认定 PPO 在所有赛段都最好。想看更小的更新实现，可先读 [强化学习 GitHub 地图](#/post/rl-github-method-map) 中的 CleanRL。

## 第二步：先读懂动作，再设计更大的网络

[官方环境说明](https://aiarena.tencent.com/hok/doc/environments/index.html) 描述了结构化观测和多分支动作；[旧版教程](https://aiarena.tencent.com/hok/doc/quickstart/first_agent.html) 展示了 `legal_action` 与 `sub_action_mask`。前者帮助判断可选动作，后者涉及某一主动作需要哪些子动作。这里引用的是公开旧接口，当前字段、形状及语义须按实际包核对。

把决策想成“先决定做什么，再给这个动作填参数”。移动、普通攻击和指向技能，不一定都需要同样的目标或方向参数。推荐按下面的顺序排查：

- 在概率归一化和采样时应用对应合法性掩码，训练计算概率时保持同一规则。
- 根据主动作确定哪些子动作头有效，不把无关头机械计入策略损失。
- 检查目标掩码与主动作的条件关系，不能只对每个头各做一次独立过滤。
- 将全无合法项当成需要追踪的协议问题；回退动作遵循 SDK 约定并记录，不能悄悄输出任意动作。

这些是本文建议的实现检查，不是对全部 SDK 的字段断言。可以先收集一小批协议样本，人工核对主动作、活跃子头、目标和执行结果。发现非法动作时，先定位掩码、索引和动作解码，再考虑增加训练量。

## 第三步：观测表示回答“现在看到了什么”

建议先整理实体字典：己方英雄、可见敌方英雄、小兵、防御塔等，各自有哪些获准使用的属性。位置统一到约定视角，血量等量纲按明确定义归一化，同时保留实体存在或有效性标记。

“不可见”“不存在”“死亡”和“有效但数值为零”不能混为一种输入。处理可变数量实体时，可比较固定槽位与共享编码后聚合；需要目标选择时，还要保留实体到动作目标索引的对应关系，避免池化后丢失目标身份。

这些是可检验的表示假设，并非保证优于基线。只有对应比赛规则允许修改特征时才做表示实验；旧公开文档的部分比赛说明限制过观测修改，不能据能拿到某字段就认为可以输入模型。

## 第四步：核对 PPO 用的概率是不是实际采样概率

理解 PPO 时，先追踪一条样本。下面是建议的实验记录契约，不是某个开发包要求的字段列表：

```text
对局标识、步号、策略版本、对手版本、英雄与阵营
观测、主动作与有效子动作、采样时使用的掩码
旧策略动作对数概率、价值估计、奖励分项
真实终止、采样截断、下一状态或自举所需信息
若使用循环策略：序列边界和初始隐藏状态
```

PPO 比较新旧策略对同一动作的概率，可以用下面的形式理解：

```text
ratio = exp(新策略的动作log概率 - 采样时旧策略的动作log概率)
```

如果采样时使用了掩码，更新时却使用未掩码分布，ratio 比较的就不是原来的行为。如果子头依赖主动作，联合概率也必须按实际有效条件构造。先检查这个一致性，再讨论 clip 系数。[PPO 算法说明](https://spinningup.openai.com/en/latest/algorithms/ppo.html)

优势估计还要区分真正终局和采样截断：任务结束后不再自举；时间限制或采样片段结束是否自举，应按任务定义和可取得的下一状态处理。不能把游戏进程崩溃直接记成正常失败并训练终局奖励。

多 actor 异步采样时，记录样本对应的策略版本与更新滞后。系统采用 actor/learner 架构，并不自动把 PPO 变为可以任意吃旧数据的 off-policy 算法；旧样本如何处理，应有明确且可检查的策略。

## 第五步：奖励先做诊断，再增加细节

下面是本站建议的实验方法。先以任务胜负作为目标指标，再看经济、经验、生存和推进等辅助信号。不要直接复制别人的权重：不同 SDK 的奖励单位、累计方式和符号可能不同。

挑选四类回放人工检查：赢但奖励低、输但奖励高、领先后送掉、长期僵持。每局分别记录各奖励项原始值、乘权重后的贡献、总回报和最终结果。这样才能判断是推塔信号被经济奖励淹没，还是策略靠拖延、重复行为获得了局部收益。

若采用“优势势函数”的差分来设计引导，要分清普通 `Phi(s_next)-Phi(s)` 与折扣形式 `gamma*Phi(s_next)-Phi(s)`。不能因为名称里有“势函数”就假定任何写法都保持原任务最优策略；终止边界、折扣和可观测状态也参与条件。起步实验只把它作为待验证奖励设计，不作理论保证。[奖励塑形的原始研究](https://people.eecs.berkeley.edu/~russell/papers/icml99-shaping.pdf)

一个便于入门的对照是：保持网络和训练预算固定，先只改变某一项辅助奖励的尺度，同时检查胜负及失败类型。如果回报更高而任务更差，就将其作为奖励投机证据继续分析，而不是宣布模型提升。

## 第六步：需要历史时，再加 LSTM

时序记忆可能帮助处理暂时不可见目标、技能过程和连续决策，但也引入序列训练问题。建议先验证前馈基线，再只改变记忆模块，保持其余条件尽量一致。

循环训练要保留片段顺序，在回合结束时重置状态，对 padding 做掩码，并明确序列起点的隐藏状态怎样得到。若使用 burn-in，需把用于恢复隐藏状态的前缀与参与损失的训练段分清。把所有转移随机打散，再把 LSTM 接在网络后面，不能自动学到正确历史。

评估时检查隐藏状态是否跨对局串用，以及线上推理是否与训练的状态更新规则一致。增加记忆后未见收益，也可能是当前观测已足够，不能先认定训练失败。

## 第七步：自博弈需要对手池，也需要留出的对手

本文建议先留一个固定基线用于长期比较，再尝试训练对手混合：固定基线、当前策略及历史快照。比例是实验变量，不提供未经验证的“最佳配比”。

只打最新自己可能产生循环克制；只打一个固定弱对手又可能过拟合。训练对手池和独立评估对手集合分别管理，明确哪些对手参与过选参。评估对局不能反过来更新策略。

有条件时按阵营和英雄分层、交换阵营配对，并保存逐局结果。报告胜、负、平、异常数量；若给出胜率，明确分母和平局处理，异常率另列。比如 `胜局/(胜局+负局+平局)` 与排除平局后的胜率不是同一指标，不应在迭代间切换口径。

用评估种子、对局数和区间表达不确定性。不要挑一次最好的小批对局结果代替稳定提升；也不要根据训练中频繁查看的对手表现，声称对所有未知对手有效。

## 六组可以排进服务器的实验

下列是待执行计划，不是已经取得的结果。每组先固定任务契约、训练预算和模型选择规则，再比较：

1. 原始官方基线重复运行：确认不同种子下的波动和异常情况。
2. 单项奖励尺度：观察任务胜负是否与奖励变化一致，保留失败回放。
3. 观测表示：仅在规则允许时比较一种归一化或实体编码方案。
4. 时序记忆：前馈与循环策略比较，同时记录推理延迟和资源开销。
5. 对手组成：固定对手与包含历史快照的对手池比较，使用相同独立评估协议。
6. 采样滞后控制：在可修改训练器的条件下，比较样本时效与训练吞吐，检查是否只是用更多交互换取收益。

对照记录实际环境步数、优化步数和用时；不同系统若这些预算不能同时匹配，就明确差异。每组尽量只检验一个主要假设，避免把奖励、网络和对手同时改动后无法归因。

## 能连接到我们课题的三个问题

合法动作和有效子头检查，可以迁移成机器人技能的前置条件验证：动作可输出，不等于当前可以执行。研究时还要加入传感与执行约束，游戏收益不能替代机器人验证。

LSTM 和轨迹边界的实验，可以连接导航的短时记忆：历史是否有用、什么时候该遗忘、错误记忆怎样影响恢复。对应 [长程任务执行](#/research?direction=rd-011)。

奖励诊断与独立对手评估，可以沉淀成 [训练与故障回放作品](#/post/embodied-kaiwu-training-roadmap) 的方法模块：让实验结果可追踪、失败可解释。这些是候选研发问题，创新性仍需通过文献、对照实验和实际实现确认。
